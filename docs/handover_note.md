# プロジェクト引き継ぎ資料 (AIアシスタント向け)

このドキュメントは、本プロジェクト（POS連携システム）の開発を引き継ぐAIアシスタント（Cursor/Codex等）に向けたコンテキストおよび現状の課題のまとめです。

## プロジェクト概要
- **目的**: 既存のPOSポータルシステム（Power-K）からスクレイピングで「商品マスタ」「入出庫履歴」「商品別売上」を取得し、Supabase（PostgreSQL）に同期してNext.jsで構築したダッシュボードで閲覧・管理する。
- **アーキテクチャ**:
  - **フロントエンド/バックエンド**: Next.js (App Router), Tailwind CSS
  - **データベース**: Supabase (PostgreSQL)
  - **スクレイピング中継**: Google Apps Script (GAS)
    - Next.js の API Route から GAS の Web App (URL) を叩き、GASがPOSサイトにログイン・スクレイピングを行い、結果（CSVなど）をJSONとしてNext.jsに返す。Next.jsはそれをSupabaseにUPSERTする。

## 商品マスタ同期の現在地（2026-08-11完了）

商品マスタの0件問題と店舗混入は修復済みです。GAS Web Appの有効デプロイは **v54** です。

Next.js側の修正は`origin/main`の`0d7e375`へ反映済みで、2026-08-11にVercel本番デプロイの成功を確認しました。

### POSの店舗識別子

以前の「店舗IDが逆転している」という推測は誤りでした。検索フォームへ渡す店舗グループIDと、CSV内の実店舗コードは別の識別子です。

| 対象 | 検索用店舗グループID | CSV内実店舗コード | CSV内店舗名 |
|---|---:|---:|---|
| 本店 | `11098` | `11053` | からつケンネル本店 |
| わんわん | `11099` | `11054` | わんわんペットセンター |

`next_app/app/api/gas/sync-products/route.ts` はこの正規マッピングを固定値としてGASへPOSTします。

### 実装済みの安全策

- GASの`dryRun`で、Drive保存・Supabase更新前にCSVの店舗、列構造、JAN件数を確認できる。
- CSV内店舗が要求店舗と違う場合は、外部データを変更せず同期を中止する。
- JANはD列（index 3）から読み、全角数字と末尾`.0`を正規化する。
- 商品名の`(w)`等から店舗を推測せず、検証済みCSVの店舗をタグに使う。
- 全UPSERT成功後だけ、今回のCSVにない商品の「対象店舗タグのみ」を外す。
- 同一JANが両店舗にある場合は、1行の`tags`を`本店,わんわん`として両所属を保持する。
- GASのURLFetch URL長上限を超えないよう、既存タグ取得は40件単位で処理する。
- Supabase同期エラーをGAS/Next.js APIが成功扱いしない。

## リアルタイム入出庫履歴（2026-08-11修復）

履歴画面の店舗選択は、商品マスタ画面と異なりセレクトボックスではありません。POS画面と同じ順序で`schTenpoGroup`へIDを設定し、`doSelectTenpoGroup`をPOSTして店舗コンテキストを確定してから検索・CSV出力します。

| 対象 | 店舗グループID | 2026/07/01〜2026/08/11の実測件数 | CSV内店舗名 |
|---|---:|---:|---|
| 本店 | `11098` | 2,426 | からつケンネル本店 |
| わんわん | `11099` | 3,387 | わんわんペットセンター |

- 商品名の`(w)`等による履歴分離案は、実データ2,426件中該当1件だけだったため採用していない。
- わんわん専用ローカル認証ファイルは使用しない。既定POS接続で両店舗を選択できる。
- Next.js APIはGAS失敗を空配列へ変換せず、エラー理由を画面へ返す。
- 商品同期・履歴APIはVercel Functionsの`maxDuration`を300秒に設定する。

### 本番画面の最終確認（2026-08-11）

Vercel本番のログイン済み画面から、店舗表示を切り替えて両機能を実行しました。

| 対象 | リアルタイム履歴の画面表示 | 商品マスタ同期の画面表示 |
|---|---:|---:|
| 本店 | `対象店舗: 本店 (11053)` / 2,532件 | CSV 3,778件 → Supabase 3,778件処理 |
| わんわん | `対象店舗: わんわん (11054)` / 3,387件 | CSV 2,754件 → Supabase 2,754件処理 |

本店の履歴画面件数には、GASのPOS履歴にSupabaseの店舗間移動・物品使用履歴を統合した行が含まれます。わんわんの先頭3行はすべてCSV内店舗名が`わんわんペットセンター`であることも確認済みです。

`next_app/pos_credentials.json`などの認証情報ファイルはコミットしないこと。

## ファイル構成
- `next_app/`: Next.jsアプリケーション本体
- `gas/`: GASのソースコード（`autoDownload.js`, `importCSV.js` など）。変更後は `clasp push` & `clasp deploy` が必要。
- `tests/gas_product_master_parser_test.mjs`: 商品CSV解析・店舗タグ統合・URL長の単体テスト。
- `tests/gas_product_master_dry_run.mjs`: GASを両店舗で確認する診断スクリプト。既定はdry-runで、実同期には明示的な`--apply`が必要。
- `tests/audit_product_store_memberships.mjs`: Supabaseの商品行・店舗所属数を変更せず監査するスクリプト。
- `tests/gas_history_diagnostic.mjs`: 店舗別の履歴件数・CSV店舗名・店舗選択ログを変更なしで確認するスクリプト。

- 環境変数は `next_app/.env.local` に記載（SupabaseキーやGASのURL）。秘密情報をログやコミットへ含めないこと。
